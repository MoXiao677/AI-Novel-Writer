# 第一阶段项目说明

AI-Novel-Writer 最终希望把长篇小说创作中的大纲、人物、正文、审核改写与历史记录放在一个平台中。原有 `README.md` 描述长期目标，本文件说明当前实际完成的范围。

## 现在已经有什么

- 四个职责独立的模块目录：数据定义、业务操作、存储、界面。
- 六类核心数据的 Python 定义，以及数据类型、编号关联、版本链校验。
- JSON 读取和转换代码，可以读取虚构示例并检查数据是否合法。
- 一份《雾港来信》示例，包含两位人物、一章正文和两版内容快照。
- 中文开发规范、架构、数据结构与下一阶段说明。

目前没有可打开的写作界面，没有保存按钮，也没有 AI 调用、数据库或自动写作功能。版本结构已经定义，版本保存和恢复操作仍待实现。

## 怎样查看

先看本文件，再看 `architecture.md`。需要了解人物和章节如何关联时，打开 `data-models.md`，对照 `examples/sample-novel/novel.json` 阅读。下一阶段的任务在 `roadmap.md` 中。

可以把 JSON 理解为有固定标签的资料卡：`title` 是书名，`content` 是正文，`id` 是不会因改名而变化的编号。Python 数据类则规定每张资料卡允许包含哪些字段。

## 怎样验证

基础代码使用 Python 3.11 或更高版本，只依赖标准库，无需 API 密钥或第三方运行依赖。这一步不是启动软件界面，而是检查项目基础是否正确。

在项目根目录打开终端，先确认 Python 可用：

```powershell
python --version
```

然后运行：

```powershell
python scripts/validate_example.py
python -m unittest discover -s tests -v
```

第一条命令会显示《雾港来信》校验通过及人物、章节、版本数量；第二条运行数据约束测试，成功时最后显示 `OK`。两条命令都不修改小说文件。测试产生的 Python 缓存由 Git 忽略。

如果 `python` 命令不可用，说明这台电脑的终端尚未配置 Python。可以让开发者使用已安装 Python 的完整路径验证，再单独配置日常开发环境。无需为本阶段购买或开通 AI 服务。

本阶段验证命令直接读取 `src/`，不用执行 `pip install`。`pyproject.toml` 记录项目名称、Python 要求和未来打包配置；打包工具不是这两条验证命令的运行依赖。

## 自己的小说放在哪里

后续本地小说约定保存在 `data/<小说项目编号>/novel.json`。本阶段尚未实现文件保存，也没有创建实际小说内容。`data/` 已加入 Git 忽略规则，后续保存功能须避免意外提交私人正文。

Git 忽略规则不会代替备份。下一阶段必须设计保存和备份流程，再让作者开始正式使用。

GitHub 用于保存软件代码和公开示例，软件里的版本记录用于保存小说内容历史；两者用途不同。上传方式见 `github-sync.md`。
