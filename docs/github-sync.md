# 本地项目与 GitHub 同步

本地项目是电脑里的工作目录；GitHub 仓库是网上保存代码与文档的地方；Codespaces 是另一份运行在云端的工作目录。这三个地方不会因为文件同名就自动同步。

每次上传前，开发者应检查文件清单，确认没有真实小说、私人配置或密钥。本项目的示例是虚构内容，可以随代码上传。作者已授权开发者维护此仓库，正常代码提交与推送可在此范围内进行。

## 由开发者帮助上传

电脑需要有 Git、可用的 GitHub 登录以及当前仓库的写入权限。作者本人通过浏览器登录并完成授权，密码与访问令牌不要发到聊天里。

如果 Git 没有作者信息，需先配置本仓库的提交姓名与邮箱。邮箱可使用作者在 GitHub 个人设置里提供的隐私邮箱；不要由程序擅自编造身份或修改全局配置。

登录和提交身份确认后，开发者可以检查改动、创建 Git 提交并推送。一次成功推送后，GitHub 页面就能看到新增目录和文件。遇到远程已有更新时，先检查差异并保护双方内容，禁止强制推送。

## 暂时不登录时

可以保留完整本地项目，后续登录后再推送，也可以使用开发者提供的第一阶段新增文件压缩包：

1. 在电脑上解压压缩包。
2. 打开自己的 GitHub 仓库，选择 `Add file` → `Upload files`。
3. 上传解压后的目录与文件，保持目录结构。压缩包只包含本次新增文件，不包含根目录已有的 README。
4. 检查文件列表，确认提交。不要直接把压缩包当成项目代码上传。

浏览器上传后，本地 Git 历史还未与网页新增提交同步。下一次继续开发前让开发者检查并合并；不要直接覆盖本地文件或删除重来。

## 在 Codespaces 中继续

GitHub 更新后，先在 Codespaces 运行 `git status --short` 检查是否有未保存或未提交内容。截图中存在尚未提交的 `AGENTS.md`，如果它仍在，应先保存它的内容，避免与远程新增文件冲突。让开发者检查这些本地变化后再拉取更新。

软件代码的 Git 历史与小说文档中的 `versions` 是不同机制。v0.2 已实现本地数据库保存与章节版本恢复；上传代码仍不代表小说已经备份。`data/`、导出与数据库文件默认被 Git 忽略。
