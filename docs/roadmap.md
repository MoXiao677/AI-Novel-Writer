# 分阶段开发计划

## 第一阶段：建立基础

本阶段交付模块目录、数据结构、JSON 示例与读取校验、基础测试和中文文档。原 README 的“基础界面”延后到下一阶段，因为作者此次明确要求优先完成架构与数据基础。

验收方式：示例校验成功；基础测试通过；原有 README 未被修改；不包含 AI API 调用和私人正文。

## 第二阶段：离线最小流程

先实现一条完整且能可靠保存内容的流程：

1. 创建一本小说项目。
2. 手动填写全书大纲和人物。
3. 新建章节，填写细纲和正文。
4. 保存内容，并保留完整版本快照。
5. 关闭后重新打开，核对内容没有丢失。
6. 查看旧版本，选择恢复时创建一个新版本。

保存功能应使用临时文件与原子替换，避免写到一半留下损坏文件；遇到外部修改须提示冲突。正式章节的改写要有作者确认，既有历史不能自动覆盖。

在业务和保存功能可验证后，增加一个简单界面。具体使用网页还是桌面形式届时确定，当前不引入界面框架。

此阶段继续离线运行，不接入模型 API。验收重点是重开后内容一致、版本可查看恢复、保存失败可以恢复原文件。

## 第三阶段：补充资料管理

在离线流程稳定后，再增加世界观、文风、搜索、导入导出等作者确实需要的能力。根据小说规模评估拆分文件和 SQLite 存储。

## 第四阶段：逐步加入 AI

作者确认后才接入模型。先增加一个可替换的模型适配器，明确费用、超时、错误处理和人工确认流程，再逐步增加审核、改写及多模型协作。

## 第五阶段：长篇一致性与完善

逐步建设剧情时间线、人物与世界观一致性检查，以及全书质量检查。每一步都应有可观察的结果，自动建议由作者选择是否采纳。
